# KRUG Mini App 0.2.4 — Visual System Polish

Самостоятельное клиентское приложение студии КРУГ: HTML / CSS / vanilla JS. Без сборки, зависимостей, backend, платежей и связи с внутренней CRM.

## Актуальный расчёт: каждый час отдельно

Для «Записи» сессия делится на части по границам 09:00 и 15:00. Каждый час внутри 09:00–15:00 стоит 1 000 ₽, вне окна — 1 200 ₽. Правило действует для всех длительностей от 1 до 8 часов, включая 2 часа. Прежние пакетные суммы для «Записи» заменены сложением почасовых цен по запросу пользователя. Другие услуги и занятость студии не изменены.

Примеры: 14:00–17:00 — 1 000 + 2 × 1 200 = 3 400 ₽; 09:00–12:00 — 3 000 ₽; 09:00–17:00 — 6 × 1 000 + 2 × 1 200 = 8 400 ₽. На выборе времени видна формула, в подтверждении — интервалы, часы и суммы. До выбора старта показана предварительная обычная цена.

priceSnapshot версии 2 сохраняет totalPrice, regularPrice, pricingPeriod (morning/regular/mixed), serviceId, date, durationHours, startTime, endTime и segments. Каждый сегмент содержит собственные границы, длительность, ставку и сумму. Адаптер пересчитывает цену при сохранении; входной цене не доверяет. Старые заявки и snapshot версии 1 не переоцениваются.

Проверки: 10 тестов правил, включая все допустимые целочасовые старты для 1–8 часов и сохранение 14:00–17:00 за 3 400 ₽. Браузерные сценарии на 360/390/430 px проверяют обновление цены при смене старта, даты и длительности, сохранение, reload и Telegram-заглушки.

## Что изменилось в 0.1.1

- Понятные подписи «Выбери услугу», «Все услуги», «Как тебя зовут?», «Отправить заявку». Описания различают запись, утреннюю запись, запись со сведением и самостоятельную аренду. Карточки показывают цену конкретной длительности, без неоднозначного «от».
- Смена услуги сбрасывает длительность, дату, время и цену; для fixed восстанавливает собственную длительность и цену. Смена длительности сбрасывает время и перепроверяет дату. Если дата не подходит, появляется «Для новой длительности выбери другую дату». Даже ошибка загрузки не оставляет старую дату выбранной.
- Первые 8 доступных дат и кнопка «Показать ещё» по 8 дат в пределах прежних 21 дня. Сегодня/Завтра выделены. Недоступные даты скрыты. Дата повторно проверяется при возврате на её экран.
- После выбора старта отображается весь интервал и пояснение о свободном времени на всю длительность.
- Сначала услуга, дата, время, длительность и итоговая цена; затем контакты. Telegram и комментарий необязательны. В Telegram поле username скрыто; доступные имя/username показаны в компактной карточке. Телефон обязателен; допускаются пробелы, скобки, дефисы и точки. Проверка формы и адаптер используют одни правила. Ошибки находятся возле полей и не стирают ввод.
- Один раскрываемый индикатор «Демо-режим» в шапке и одно объяснение. После сохранения — «Демо-заявка создана». `config.js` содержит `DEMO_MODE`; при false тексты меняются на «Заявка отправлена». Это только переключатель представления: API/сервер он не подключает.
- Убраны неработающие кнопки переноса и отмены. Существующие статусы данных сохранены: request / confirmed / cancelled. В production-представлении они отображаются как «Заявка отправлена» / «Подтверждено» / «Отменено».
- Содержимое прокручивается отдельно от нижней CTA; кнопка не накладывается на поля или даты. Высота приложения реагирует на visualViewport. Ошибки сохранения и занятого времени объясняют следующий шаг; при конфликте открывается выбор времени с сохранёнными контактами.

## Файлы и запуск

- `index.html` — точка входа, шапка и единственный индикатор демо.
- `styles.css` — мобильные экраны, доступные состояния, отдельная область прокрутки и нижняя CTA.
- `config.js` — простой флаг DEMO_MODE.
- `app.js` — UI, навигация, bookingDraft и полевые ошибки.
- `booking.js` — цена, длительность, московские даты, интервалы, проверка контактов и переходы состояния.
- `data.js` — асинхронный mock-адаптер и localStorage.
- `telegram.js` — необязательный адаптер WebApp, prefill, системный «Назад» и safe-area.
- `krug-wordmark.png` — предоставленный логотип шапки; `logo.svg` — иконка.
- `tests/` — проверки правил и сценариев браузера, внешние инструменты не включены в приложение.

В рабочей папке CRM приложение находится в `mini-app/`; отдельный GitHub-репозиторий содержит эти файлы в корне. Для preview раздавать именно эту папку статическим HTTP-сервером. Можно открыть index.html напрямую; сохранение зависит от поддержки хранилища браузером. Код приложения не импортирует внутреннюю CRM.

## Сохранённые правила

Цены не менялись. Выбор доступен только для явно заданных значений priceTiers; отсутствующие цены не рассчитываются. Fixed использует price и defaultDurationHours, пропуская экран длительности. В каталоге нет выдуманной fixed-услуги; этот путь проверяется фикстурой.

Одна общая студия: весь интервал [start, end) должен быть свободен. Рабочее mock-окно 09:00–23:00 МСК, начало каждый час, воскресенье закрыто. Занятый интервал 13:00–15:00 или 17:00–19:00; сохранённые неотменённые заявки также занимают время. Горизонт — 21 день. Для обычной записи стоимость каждого часа определяется его попаданием в окно 09:00–15:00 МСК. Старый morning-id сохранён для совместимости с историей, но скрыт из клиентского каталога. Правила занятости студии не менялись.

Ключ данных `krug_mini_app_bookings_v1` не менялся. Статус новой заявки — request, один mock-client: krug-mock-client. «Мои записи» фильтруется по нему. requestId защищает повторную отправку; Web Locks, если доступны, сериализуют сохранение между вкладками. Повреждённое хранилище не перезаписывается. Браузерное хранение не является серверной изоляцией пользователей.

UI работает через Promise-методы адаптера:

```js
getServices()
getService(id)
getAvailability(date)
getAvailableSlots(date, durationHours, serviceId /* optional */)
createBooking(data)
getMyBookings()
```

Telegram-адаптер безопасен без WebApp. initTelegram/getTelegramUser/expandApp/closeApp сохранены; isTelegram сообщает только о наличии WebApp. initDataUnsafe служит исключительно prefill, не аутентификацией. Настоящий SDK и отправка сообщений пока не подключены.

## Service Entry Flow 0.2.2

Главная содержит фиксированные четыре entry cards: Запись, Запись + сведение, Аренда, Прочие услуги. Первые три сразу открывают длительность; Back возвращает домой. Продолжить запись появляется только с черновиком. Новая услуга требует подтверждения сброса; просмотр прочих услуг сам по себе черновик не меняет.

Публичный контракт каталога: publicVisible, publicCategory (primary/other), publicName, publicDescription, price, pricingType, duration, defaultDuration. Длительности — в часах, null означает отсутствие данных. priceTiers и defaultDurationHours сохранены для совместимости. Для почасовых услуг price=null, источником цены остаются прежние tiers и mixed pricing.

Источник дополнительных услуг — migrationServiceCatalog внутренней CRM (app.js): сведение 2 часа от 4000, битмейкинг 1 час от 5000, сведение + мастер 3000 без длительности. Первые две используют pricingType=minimum, предварительную цену и snapshot isEstimate; они сразу открывают дату. Для третьей доступен информационный экран с возвратом, без availability и создания заявки до уточнения длительности. CRM не импортируется во время работы приложения.

Проверки: прежние booking/profile/loyalty сценарии, 15 unit tests, все четыре входа, Back, отказ/подтверждение сброса, каталог прочих услуг, известная/неизвестная длительность, мобильные размеры 360×800, 390×844, 430×932.


## Актуальные правила длительности и аренды

«Запись + сведение» и все прочие услуги выбираются от 2 до 8 часов. У прочих услуг selectDuration=true: fixed/minimum сохраняют прежнюю цену, длительность задаёт занятость. В UI указано «от», почасового умножения нет. Предыдущий экран неизвестной длительности удалён.

Аренда начинается с выбора формата. Почасовая сохраняет прежние тарифы. День: 10:00–22:00, 12 часов, 9000 ₽. Ночь: 22:00–10:00 следующего дня, 12 часов, 7500 ₽. Пакеты хранятся в каталоге аренды и доступны через getService; на главной новых карточек нет. Пакет ведёт сразу к дате и подтверждению, начало фиксировано. Сохранение повторно проверяет цену и весь интервал.

Пакеты разрешают ночные часы вне обычного окна 09–23; закрытые даты и занятость сохраняются. Проверка пересечений делит ночной интервал по суткам; сохранённая ночная аренда блокирует следующее утро. В текущем mock каждый рабочий день содержит занятый дневной интервал, поэтому пакет День не имеет доступных дат. Это ожидаемо; его успешное создание проверено на отдельной фикстуре пустой студии, без изменения рабочего mock.

Проверки: 16 unit tests, прежние booking/profile/loyalty сценарии, создание обоих пакетов на 360×800, 390×844, 430×932, пересечения следующего дня и точная граница 10:00. Реальные устройства/Telegram не проверялись.

## Профиль, приветствие и отмена записей

Первый запуск показывает обязательное приветствие с именем и телефоном. Профиль сохраняется отдельно в krug_mini_client_v1; Telegram user ID считывается из адаптера как неподтверждённые клиентские данные, без аутентификации и изменения локального clientId. Данные используются в новых черновиках. Фото загружается в профиле, JPEG/PNG/WebP до 8 МБ, уменьшается до 512 px и сохраняется локально; ошибка хранилища не стирает прежнее фото.

cancelBooking сохраняет cancelledAt и cancelledAfterStart. Отмена до начала скрыта из списков, отмена после начала сохраняется в истории. Данные не удаляются, отменённая запись освобождает занятость. Отмена требует подтверждения. История бонусов осталась только в модальном окне; индикатор «Демо-режим» скрыт, бизнес-данные всё ещё локальные mock/demo.

## Списание и накопление бонусов

На подтверждении switch useBonuses по умолчанию выключен. При включении списывается min(balance, price), amountDue = price − bonusSpent; остаток сохраняется. Итог пересчитывается адаптером при создании, исходный тариф/priceSnapshot не меняется. Движения бонусов выводятся из записей, поэтому повтор requestId не вызывает двойного списания и не требуется отдельная несогласованная запись баланса.

При отмене до начала бонусы возвращаются; после начала не возвращаются. completePaidBooking(id) — mock-событие оплаченной завершённой сессии, без платежного интерфейса или реальной оплаты. Оно доступно после окончания сессии; при выключенном switch начисляет 10% стоимости (целые бонусы, округление вниз), при включённом не начисляет. Повторное событие идемпотентно. Будущий API/CRM должен выдавать это событие после подтверждения оплаты и завершения, отправка заявки начислений не создаёт.

Проверки: 19 unit tests плюс мобильный browser flow со switch, сохранением суммы к оплате, границей списания, возвратом, начислением и повторными запросами. Фон страницы однотонный, акценты ограничены карточками и шапкой.
